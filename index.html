What is a Random Variable?

        
In Postman, they are officially called Dynamic Variables. They generate a new random value every time you click Send, so you don't have to type test data by hand. They are written inside double curly braces and start with a $ sign:

        
      


      
      

        
Why use them?

        
    
          
  • To Create User / Register without the email or username repeating (avoids "already exists" errors).
    • 
          
  • To test with different data on every run.
    • 
          
  • To fill POST and PUT bodies quickly.
    •

Quick Tips

        
    
          
  1. Use {{$randomEmail}} in Register requests to avoid duplicate emails.
    2. 
          
  2. If you need the same value across several requests, store it in a variable using a script.
    3. 
          
  3. Random values make bugs harder to reproduce, so store the value (or print it with console.log) to be able to repeat the same case.
    4. 
        

      


      
      

        
Which way should I use them?

        
Choose by what you need the value for. There is no single way that fits every request.


        

          
            

              If you need
              Do this
            

          
          
            

              A value once, in one place (a new name or email for one request)
              Write the dynamic variable directly, for example {{$randomEmail}}.
            

            

              The same value in more than one place (Register then Login, or an assertion)
              Generate it once in a Pre-request Script and store it in a variable.
            

            

              An exact value (an invalid email, an empty field, a boundary number)
              Use fixed data. Do not use random values for negative or boundary tests.
            

            

              A value the server creates (an ID or a token)
              Save it from the response in the Tests tab, then reuse it in the next requests.

Best Practices

        
    
          
  1. Test on a test or staging environment. Random data creates real records, so never run it against production.
    2. 
          
  2. Prefix your test data. A value like qa_{{$randomUserName}} makes your records easy to find and delete later.
    3. 
          
  3. Make values unique on purpose. {{$randomInt}} only gives a number from 0 to 1000, so repeats can happen. Combine it with {{$timestamp}}, as in qa_{{$timestamp}}_{{$randomInt}}@example.com.
    4. 
          
  4. Check the API's validation rules. A random password or phone number may be rejected if the API expects a specific format, for example an uppercase letter and a symbol. In that case, build the value from fixed parts.
    5. 
          
  5. Keep fixed data for negative and boundary tests. Random values are for the "any valid value" cases only.
    6. 
          
  6. Store generated values in the smallest scope that works. Use pm.variables.set for a single run, pm.collectionVariables.set for a flow across requests, and pm.environment.set when the value depends on the environment.
    7. 
          
  7. Log what you generate. Print it with console.log so you can repeat a failed case with the same data.
    8. 
          
  8. Clean up after the run. End the flow with a DELETE request that uses the stored ID.
    9. 
        

      


      
      

        
Tips and Tricks

        
    
          
  • See the real values. Open the Console at the bottom of Postman. It shows each request after the variables are replaced.
    • 
          
  • Watch for typos. A misspelled name is not replaced, so the text is sent as it is. If you see {{$randomEmial}} in the Console, fix the name.
    • 
          
  • Quotes in JSON. Put quotes around text values and leave them off numbers: "name": "{{$randomFullName}}" and "age": {{$randomInt}}.
    • 
          
  • Mix text and variables. Several can sit in one value: Test {{$randomFullName}} or user_{{$randomInt}}@mail.com.
    • 
          
  • Use them anywhere in the request. They work in the URL, Params, Headers and Body, not only in the Body.
    • 
          
  • In scripts, use pm.variables.replaceIn(). Writing {{$randomEmail}} inside script code does not resolve by itself. Pass it as text to replaceIn, as in the examples above.
    • 
          
  • Run the same request many times. Use the Collection Runner and set Iterations. New values are generated on every iteration.
    • 
        

      


      
      

        
Summary

        
    
          
  • Dynamic Variables = ready-made random values that start with $.
    • 
          
  • They are regenerated on every Send.
    • 
          
  • To keep a value fixed: pm.variables.replaceIn() + pm.collectionVariables.set().
